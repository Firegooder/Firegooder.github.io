CXL.cache 和 CXL.mem

CXL 协议里，最容易混淆的是 CXL.cache 和 CXL.mem。两者都和内存有关，但关注点不同：

  • CXL.cache：解决 Host 和 Device 之间的缓存一致性问题。
  • CXL.mem：让 Host 可以访问 Device 上的内存，或者让 Device memory 被纳入系统地址空间。

简单说：

一、CXL.cache

CXL.cache 允许 CXL 设备缓存 Host 内存中的数据。

比如 Type-2 加速器、GPU、DPU、AI 加速器在运行任务时，可能需要频繁访问 Host 内存中的输入数据、descriptor、page table、模型权重或中间结果。如果每次都访问 Host DRAM，延迟会比较高。所以设备可以把部分 Host 内存数据缓存到自己侧。

但是一旦设备也缓存 Host 数据，就会出现一致性问题：

这就是 CXL.cache 要解决的问题。

1. cacheline 粒度

CXL.cache 的数据传输粒度通常是 64B cacheline。

也就是说，它不是随便传 1KB、4KB 或 1MB 的业务数据，而是围绕一条 cacheline 做一致性管理。

在模拟器或者项目实现中，一般也会用 64B 作为 cache directory 的管理单位。

六、HDM-H 和 HDM-D

CXL.mem 里经常会看到 HDM-H 和 HDM-D。

1. HDM-H

HDM-H 主要用于 Type-3 内存扩展设备。

Type-3 设备本质上更像一条 CXL 内存条，它没有复杂的计算单元去主动修改 Host 内存，也通常不需要 CXL.cache。

2. HDM-D

HDM-D 更常见于 Type-2 设备，也就是带计算能力、带设备本地内存的加速器。

Type-2 设备既可能被 Host 访问本地内存，也可能自己运行计算并访问这块内存。因此一致性更复杂。

为什么要有 bias？

因为 Type-2 设备的本地内存可能既被 Host 访问，也被设备计算单元访问。如果每次访问都做完整一致性处理，开销很高。bias model 可以让当前主要访问方获得更高效的访问路径。
